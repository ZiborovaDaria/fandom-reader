## Why

Сейчас книги попадают в библиотеку только через ручной SAF-пикер («Выбрать файл»). На устройстве уже лежат EPUB/FB2 в типичных папках, но пользователь должен импортировать их по одному. Нужен основной поток: найти все подходящие файлы, добавить в библиотеку и показать отсортированный список, оставив ручной импорт запасным.

## What Changes

- Скан типичных папок устройства (Downloads, Documents, Books) на `.epub` / `.fb2`
- Пакетное добавление найденных файлов в библиотеку через существующий pipeline классификации/парсинга (`ImportCoordinator`)
- Скан как основной способ пополнения библиотеки (действие в UI библиотеки / автозапуск при открытии при наличии разрешения)
- Ручной SAF-импорт сохраняется как запасной путь
- После скана библиотека остаётся отсортированной (title / существующий порядок полок и фильтров по `canonicalKey`)
- Дедупликация повторных сканов по уже известной идентичности файла/работы (не плодить дубликаты)

## Capabilities

### New Capabilities

- `device-library-scan`: обнаружение EPUB/FB2 в типичных папках, пакетный импорт, прогресс/ошибки скана, запрос разрешений на чтение хранилища

### Modified Capabilities

- `fanfic-library`: основной CTA пополнения — скан устройства; списки после скана остаются отсортированными; ручной импорт вторичен в UI
- `portal-import`: пакетный импорт из результатов скана переиспользует classify/parse/upsert; ручной одиночный импорт остаётся fallback

## Impact

- `:feature:library` (CTA скана, статус, связь с разрешениями), `:feature:import` (SAF как secondary), `:source:api` / `ImportCoordinator` (batch entry), `:app` (permissions в манифесте)
- Android storage permissions / доступ к публичным каталогам (API 26–33+ различия)
- Unit-тесты на сканер (fake FS) и дедуп; без live-сети
