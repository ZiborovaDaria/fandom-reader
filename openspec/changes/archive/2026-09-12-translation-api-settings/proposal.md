## Why

Ключ Gemini уже хранится в EncryptedSharedPreferences, но в приложении нет экрана настроек, куда пользователь может его ввести. Без ключа Hilt выбирает `FakeTranslationProvider` один раз при старте, поэтому «перевод» фактически подменяет текст префиксом `[RU]`, а живой Gemini из UI недоступен. Нужно закрыть настройки ключей и привести pipeline перевода к рабочему состоянию.

## What Changes

- Экран настроек перевода: ввод / сохранение / очистка API-ключа нейросети (Gemini как primary), ключ маскируется в UI и не логируется
- Привязка сохранённого ключа к выбору провайдера **на момент запроса**, а не только при создании Singleton
- Проверка и доработка функции перевода: metadata (title/summary) и главы через `TranslationPipeline`; понятная ошибка/подсказка, если ключ не задан и живой перевод невозможен
- Unit-тесты остаются на `FakeTranslationProvider`; live Gemini не требуется в CI

## Capabilities

### New Capabilities

- `translation-settings`: экран и поведение хранения ключей нейросетей для перевода

### Modified Capabilities

- `ao3-translation`: выбор провайдера по сконфигурированному ключу в runtime; корректный EN→RU путь без тихого Fake при ожидании нейросети; доступность перевода глав после настройки ключа

## Impact

- `:app` навигация (маршрут Settings), `:feature:translation` (`GeminiSettings`, `GeminiProvider`, DI), UI библиотеки/ридера для запуска перевода и перехода в настройки
- Существующее encrypted-хранилище `gemini_secure_prefs` переиспользуется; новые секреты в git не появляются
- Зависимости: без новых сетевых SDK; Material 3 Compose для экрана настроек
